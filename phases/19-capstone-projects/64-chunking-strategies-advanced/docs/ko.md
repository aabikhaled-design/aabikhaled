# 청킹 전략 비교 (Chunking Strategies, Compared)

> 청킹은 검색기가 앞으로 무엇을 꺼내 올 수 있는지를 결정한다. 경계를 잘못 잡으면 어떤 임베딩 모델도, 어떤 리랭커도, 어떤 LLM도 그 뒤에서 그 손해를 되돌리지 못한다.

**Type:** Build
**Languages:** Python
**Prerequisites:** Phase 11 lessons 04 (embeddings), 06 (RAG), 07 (advanced RAG); Phase 19 Track B foundations (lessons 20-29)
**Time:** ~90 minutes

## 학습 목표 (Learning Objectives)
- 청킹 전략 다섯 가지를 맨바닥에서 구현한다. 고정 길이 창, 문장 단위, 재귀 분할, 의미 군집, 마크다운 제목 기반 구조 분할이다.
- 정답 구간이 표시된 고정 말뭉치에서 recall@k를 측정하고, 왜 산문에서는 어떤 전략이 이기고 기술 문서에서는 다른 전략이 이기는지 설명한다.
- 청크 길이 분포를 읽고, 각 전략이 만들어 내는 실패 양상을 알아본다. 홀로 떨어진 문장, 기호 중간에서 잘린 토막, 제목만 남은 청크, 주제가 흘러가 버리는 현상이다.
- 벤치마크를 돌리지 않고도 새 말뭉치의 기본 전략을 고른다. 문서 종류와 평균 문단 길이, 그리고 그 형식에 명시적인 구조가 있는지 세 가지만 보면 된다.

## 문제 (The Problem)

모든 RAG 파이프라인은 원본 문서를 조각으로 자르는 데서 시작한다. 임베딩 모델에 들어갈 만큼 작으면서, 조각 하나가 스스로 완결된 생각을 담을 만큼은 커야 한다. 어디에서 자를지는 하이퍼파라미터가 아니다. 검색기가 앞으로 돌려줄 수 있는 것의 상한선이다.

"예산 중단 기준이 어떻게 되느냐"라고 묻는 질의는, 그 기준값을 담은 청크에 닿을 수 있을 때만 성공한다. 고정 길이 분할기가 그 기준값을 주변 맥락에서 떼어 내 잘랐다면, 임베딩은 다른 군집으로 옮겨 가고, BM25 점수는 떨어지고, 리랭커는 잡음만 보게 되고, LLM이 만들어 내는 답은 틀린다. 2024년 논문 「LongRAG: Enhancing Retrieval-Augmented Generation with Long-context LLMs」는 오직 청킹 선택만으로 검색 재현율이 절댓값 기준 35퍼센트포인트나 오르내리는 것을 측정했다. 2025년에 나온 맥락 청크 머리말 관련 후속 연구가 그 격차를 줄였지만 없애지는 못했다.

이 레슨에서는 다섯 전략을 나란히 만들고, 정답 구간이 표시된 고정 말뭉치에 돌려서, 재현율 수치를 직접 읽어 보게 한다.

### 고정 길이 창

가장 단순한 기준선이다. N글자마다 자른다. 겹침을 두면, N번째 위치에서 잘린 문장이 N에서 겹침만큼 앞에서 시작하는 청크 안에 온전히 들어간다. 빠르고 결과가 일정하지만 경계 처리가 형편없다. 기본값이 아니라 대조군으로 써라.

### 문장 단위

정규식이나 간단한 상태 기계로 문장 경계에서 자른다. 목표 글자 수까지 문장을 하나 이상 모아 청크를 만든다. 단어 중간에서 자르지는 않는다. 다만 문단 중간이나 절 중간에서는 여전히 자른다. 초기 RAG 파이프라인 상당수의 기본값이었고, 다른 구조가 없는 산문에는 그런대로 쓸 만하다.

### 재귀 분할

2023년 무렵의 라이브러리들이 퍼뜨린 계층 전략이다. 가장 강한 구분자(빈 줄, 문단)로 먼저 자르고, 안 되면 다음 구분자(줄바꿈)로, 그다음에는 문장으로, 마지막에는 글자 단위로 내려간다. 청크가 목표 크기에 들어오면 재귀가 끝난다. 구조가 들쭉날쭉한 문서에서 강하다. 구간마다 알맞게 적응하기 때문이다.

### 의미 군집

모든 문장을 임베딩한다. 그리고 주제 중심에 가까운 연속된 문장들을 한 덩어리로 묶는다. 지금까지 모은 중심과의 유사도가 기준 아래로 떨어지면 거기에서 자른다. 경계가 글자 수가 아니라 의미를 반영한다. 만드는 데 시간이 더 걸리고 임베딩 모델에 좌우되지만, 한 문단 안에서 주제가 바뀌는 문서에서도 잘 버틴다.

### 마크다운 제목 기반 구조 분할

마크다운이나 reStructuredText, RFC 형식의 번호 매긴 절처럼 구조가 명시된 문서라면 제목 경계에서 자른다. 각 청크는 제목 하나와 그 아래의 모든 내용이 되며, 같은 수준이나 더 높은 수준의 다음 제목 앞에서 끝난다. 주제별로 가장 작은 청크가 나오지만, 말뭉치의 형식이 잘 갖춰져 있을 때만 쓸 수 있다.

### recall@k가 경계 선택을 재는 방식

정답이 표시된 질의에는 원본 문서 안에서 답이 놓인 정확한 글자 위치가 붙어 있다. 청킹을 마친 뒤 이렇게 묻는다. 검색기가 돌려준 상위 k개 청크 가운데 그 정답 구간과 겹치는 것이 하나라도 있는가? 있으면 그 질의의 recall@k는 1이고, 없으면 0이다. 그것을 질의 집합 전체에 대해 평균 낸다. 전략마다 같은 평가를 돌리면, 그 차이가 지금 가진 말뭉치에서 어떤 경계 정책이 살아남는지를 보여 준다.

## 직접 만들기 (Build It)

`code/main.py`에 다음을 구현한다.

- `fixed_window(text, size, overlap)`. 기준선이다.
- `sentence_chunks(text, target)`. 단순한 문장 묶기다.
- `recursive_split(text, separators, target)`. 계층 재귀 분할이다.
- `semantic_chunks(text, similarity_threshold)`. 결정적인 모의 임베딩 위에서 중심을 기준으로 묶는다.
- `structural_markdown(text)`. 제목을 인식하는 분할기다.
- `mock_embed(text, dim)`. 해시 기반 임베딩이며, 네트워크 없이 루프를 돌리기 위한 것이다.
- `DenseIndex`. Phase 19 Track B의 하이브리드 검색 레슨과 같은 형태다.
- `eval_recall(strategy, corpus, queries, k)`. 비교 루프다.
- 고정 말뭉치에 모든 전략을 돌려 recall@k 표를 출력하는 `main()`.

다음으로 실행한다.

```bash
python3 code/main.py
```

출력은 작은 표 하나다. 행은 전략이고 열은 k 값이다. 구조가 있는 고정 데이터에서는 문장 단위가 진다. 마크다운 고정 데이터에서는 구조 분할이 이긴다. 여러 형식이 섞인 고정 데이터에서는 재귀가 제 몫을 해낸다. 재귀가 구간마다 적응하기 때문이다. 쓸 만한 구조 단서가 없는 산문 고정 데이터에서는 의미 군집이 이긴다.

## 표가 가려 주지 않는 실패 양상 (Failure modes the table will not hide)

**홀로 떨어진 문장.** 문장 묶기는 주제 문장이 빠진 청크를 만들어 낸다. 그러면 임베딩이 엉뚱한 군집을 가리킨다.

**기호 중간에서 잘린 토막.** 코드나 YAML 안에서 고정 길이로 자르면 식별자가 반으로 쪼개진다. 그 두 조각은 잡음으로 임베딩된다.

**제목만 남은 청크.** 마크다운 구조 분할은 `## 제목`만 들어 있는 청크를 내놓기도 한다. 그런 것은 걸러 내거나, 다음 청크의 첫 문단을 붙여 주어라.

**주제가 흘러가는 현상.** 말뭉치 전체가 한 주제로 고르게 채워져 있으면 의미 군집은 덜 자른다. 5,000자짜리 청크 하나에 구체적인 답이 여러 개 뭉쳐 들어가고, 임베딩은 흐릿해진다. 의미 군집에 글자 수 상한을 함께 걸어라.

**낡은 임베딩.** 의미 군집은 임베딩 모델을 쓴다. 모델을 바꾸면 청크도 바뀐다. 청킹용 모델을 검색용 모델과 따로 고정해 두거나, 색인을 함께 다시 만들어라.

## 벤치마크 없이 기본값 고르기 (Choosing a default without running the benchmark)

새 말뭉치의 기본 청커는 세 가지 성질로 정한다.

| 성질 | 값 | 기본값 |
|----------|-------|--------|
| 문서 종류 | 구조 없는 산문 | 재귀 분할, 목표 800자 |
| 문서 종류 | 마크다운, RFC, API 문서 | 마크다운 구조 분할 |
| 문서 종류 | 코드 | AST를 인식하는 분할(이 레슨 범위 밖이며 Phase 19 레슨 02를 보라) |
| 문단 길이 | 길고 주제가 하나 | 문장 단위, 목표 500자 |
| 문단 길이 | 짧고 주제가 섞여 있음 | 의미 군집, 기준 0.6 |

판단이 서지 않으면 재귀 분할을 골라라. 단일 전략 가운데 가장 강한 기준선이다.

## 실제로 써 보기 (Use It)

실무에서 지킬 것들이다.

- 새 파이프라인을 내보내기 전에 평가를 돌려라. 쓰는 라이브러리의 기본 전략을 그냥 믿지 마라.
- 임베딩 모델이나 말뭉치 구성이 바뀔 때마다 평가를 다시 돌려라. 어느 전략이 이기는지는 말뭉치에 따라 달라진다.
- 청크 메타데이터에 전략 이름을 남겨 두라. 나중에 성능이 나빠졌을 때 원인을 짚을 수 있다.

## 연습 문제 (Exercises)

1. 여섯 번째 전략을 추가하라. 글자 수 대신 `tiktoken`을 써서 토큰 단위 창으로 자르는 방식이다. 같은 고정 데이터에서 고정 길이 창과 비교하라.
2. 산문 고정 데이터에 코드 블록을 30퍼센트 섞어 넣어라. 표를 다시 뽑아라. 마크다운 구조 분할을 뺀 모든 전략이 왜 재현율을 잃는지 설명하라.
3. 결정적인 임베딩을 실제 프로젝트에서 쓰는 공급자의 임베딩으로 바꿔라. 의미 군집의 재현율이 얼마나 달라지는지 재라. 전략 사이의 격차가 벌어지는지 좁혀지는지 보고하라.
4. 청크마다 `summary` 항목을 추가하라. 중심 내용을 한 문장으로 적은 설명이다. 그것을 청크 본문에 덧붙여 평가를 다시 돌리고, 재현율이 얼마나 오르는지 재라.

## 핵심 용어 (Key Terms)

| 용어 | 흔히 쓰는 뜻 | 정확한 뜻 |
|------|-----------------|------------------------|
| Recall@k | "맞는 청크를 가져왔나" | 상위 k개 청크 가운데 정답 구간과 겹치는 것이 있는 질의의 비율 |
| Chunk overlap | "슬라이딩 윈도" | 앞 청크의 마지막 N글자를 다음 청크에 다시 넣는 것 |
| Structural splitter | "제목을 인식하는 청크" | H1·H2·H3 경계에서 자르며, 제목 문구도 청크의 일부가 된다 |
| Semantic chunker | "주제를 인식하는 청크" | 문장을 임베딩해 중심과의 유사도로 묶고, 주제가 바뀌면 자른다 |
| Centroid drift | "주제 전환" | 지금까지의 평균과 다음 문장 사이의 코사인 유사도가 기준 아래로 떨어지는 것 |
